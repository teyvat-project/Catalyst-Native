## Phase 1 spec からの変更

Phase 1 の spec では「Phase 3 では上部の写真領域がそのままピン編集キャンバスになる」としていたが、**専用のピン編集画面にする**。編集画面の写真ページャは左右スワイプで写真を切り替えるため、ピンのタップ・ドラッグと衝突し、写真も小さいため。

## サーバー側の制約

- `reference` は写真 1 枚につき最大 20 件。各ピン:
  - `x`, `y`: 元画像に対する 0〜10000 の**整数** (万分率)。アプリの表示側 (`media-pin-overlay.tsx`) と同じ座標系
  - `order`: 0〜19 の整数
  - `reference`: 既存アイテムの ID (uuid)。無ければ保存時にサーバーが新しいアイテムを作る
  - `type`: `avatar` / `cloth` / `accessory` / `hair` / `gimmick` / `other`
  - `name`: 1〜128 文字
  - `description`: 1024 文字まで、`externalUrl`: URL
  - `author`: 新しいアイテムを作るときは**必須** (無いと `createOrGetItem` が例外を投げ、**保存全体が失敗する**)
- `externalUrl` が既存アイテムと一致すれば、サーバーはそのアイテムに寄せる (非表示化されたアイテムなら失敗する)。

## 1. 導線とピン編集画面

- 「この写真の設定」の「写っている人」の下に **「ピン」** 行を足す。値は「n 件」/「未設定」。タップで、表示中の写真のピン編集画面を開く。
- ピン編集画面はフルスクリーンの `Modal` (iOS `pageSheet`)。中で `react-native-gesture-handler` を使うため、モーダルの中に `GestureHandlerRootView` を置く。
- ヘッダー: 左「キャンセル」、中央「ピン n/20」、右「完了」。写っている人の選択と同じく、モーダルの中では下書きを編集し、**「完了」で編集画面に反映**、「キャンセル」では反映しない。
- 上部に写真 (contain 表示、画面の上半分程度の高さ)。写真の上に番号付きのピンを重ねる。
  - **写真をタップ** → その位置にピンを追加し、そのピンのフォームを開く。レターボックス (余白) のタップは無視する。
  - **ピンをタップ** → そのピンのフォームを開く。
  - **ピンをドラッグ** → 移動。写真の範囲内に収める。
  - 21 件目を追加しようとしたら追加せず `Alert.alert("エラー", "写真1枚につき最大20件までピンを設定できます")`。
- 写真の下にピン一覧:
  - 各行: 番号、アイテム名 (未入力なら「未設定のピン」)、種類、「上へ移動」「下へ移動」、「ピンを削除」
  - 0 件なら「まだピンが設定されていません。写真をタップしてピンを追加してください」
  - 一覧の順番がそのまま `order` (0 から振り直す)。ピンの番号も一覧の順番。
- 行をタップでもそのピンのフォームを開く。

## 2. ピンのフォーム

ピン編集モーダルの中のステップとして出す (Phase 2 のワールド選択と同じく、モーダル内で進む・戻る)。各ステップのヘッダー左は「戻る」。

1. **アイテムを選択** (`reference` があるピン、または何も入力されていないピンはここから)
   - 「作者で絞り込む」行 (値は作者名 /「すべての作者」)。タップで作者検索 (Phase 2 の作者検索ステップを流用) を開き、先頭に「すべての作者」を出す。この絞り込みはプラットフォームを問わず検索する (`platform` を付けない。Web 版 `ItemAuthorFilter` と同じ)。作者の登録はここでは出さない。
   - 検索欄「アイテム名で検索」。300ms debounce して `client.epiclese.v1.items.get({ query: { q, author } })`。
   - 結果は「名前（作者名）」と種類。選択中に ✓。0 件は「該当するアイテムが見つかりません」。
   - 選んだら、ピンを `reference: item.id`, `type`, `name`, `description` (空なら外す), `externalUrl` (null なら外す) にし、`author` を外して、ピン編集画面へ戻る。
   - 末尾に「新しいアイテムを作成」→ ステップ 2。
2. **アイテムを新規作成** (`reference` が無く、名前か作者が入っているピンはここから)
   - 種類: アバター / 衣装 / アクセサリー / ヘアー / ギミック / その他 (チェック付きの行を並べる。初期値「その他」)
   - 名前 (必須、128 文字まで、プレースホルダ「例：ネオンジャケット」)
   - 作者 (必須)。行をタップで作者検索 → 見つからなければ作者登録 (どちらも Phase 2 のステップを流用し、写真のプラットフォームで検索する)。写真のプラットフォームが未設定なら行を無効にし「先にプラットフォームを選択してください」を出す。
   - 販売ページ URL (任意、プレースホルダ `https://booth.pm/ja/items/...`)
   - 説明 (任意、1024 文字まで、複数行)
   - 入力を変えたら `reference` を外す (Web 版と同じ)。
   - 「検索に戻る」でステップ 1 へ。
3. どちらのステップにも「ピンを削除」を置く。
4. 新しく足したピンを、アイテムも入力も無いまま (Web 版 `isPinUntouched`) フォームから戻ったら、そのピンは捨てる。

## 3. 入力の確認

新しいアイテムの作者が無いと保存全体が失敗するため、ピン編集画面の「完了」で全ピンを確認する。足りないピンがあれば反映せずに留まり、`Alert.alert("エラー", "n 番のピンの入力が足りません")` (n は最初の 1 件の番号) を出す。ピンとして有効なのは:

- `reference` がある、または
- 名前が 1〜128 文字、作者がある、`externalUrl` が無いか `http(s)://` で始まる URL、説明が 1024 文字まで

## 4. モデル

新しく `src/models/epiclese-pin-editor.ts` に純粋関数を置き、テストする (Phase 1 / 2 の `epiclese-metadata-editor.ts` が大きくなりすぎないよう分ける):

- 座標変換: 表示領域の大きさと元画像の大きさから contain の実描画矩形を求め、タップ位置 → 0〜10000 の整数 (範囲外は `inBounds: false`)、0〜10000 → 表示位置。ドラッグは 0〜10000 に収める。
- ピンの追加 (上限 20、`type: "other"`, `name: ""`)、移動、削除、上へ / 下へ。追加・削除・並べ替えのたびに `order` を 0 から振り直す。
- アイテムを選んだときのピンの更新、新規作成の入力の更新 (`reference` を外す)。
- `isPinUntouched`、ピンの確認 (上の 3 の規則)。

保存は Phase 1 / 2 と同じく全置換。ピン編集は写真の `reference` だけを差し替え、`platform` / `world` / `users` / `privacyMetadata` は変えない。

## 5. 検証

### ユニットテスト (jest)

- 座標変換: 横長・縦長の写真でレターボックスを除いて変換できる、余白は `inBounds: false`、端は 0 と 10000、結果は整数。
- 21 件目は追加されない。削除・並べ替えで `order` が 0 から連番になる。先頭の「上へ」と末尾の「下へ」は何もしない。
- アイテムを選ぶと `reference` と表示用の値が入り `author` が外れる。新規作成の入力で `reference` が外れる。
- ピンの確認: `reference` あり → 有効 / 名前なし・作者なし・不正な URL・説明 1025 文字 → それぞれ無効。
- 往復: ピン編集の前後で `platform` / `world` / `users` / `privacyMetadata` が変わらない。

### 画面テスト

- ピン編集画面: 21 件目で Alert が出て追加されない / 足りないピンがあると「完了」で反映されず Alert が出る / 何も入力しないまま戻ったピンは消える / 「キャンセル」では反映されない。

### 手動確認 (iOS シミュレータ、サインイン済み)

- 写真をタップしてピンを追加し、既存アイテムを選んで保存 → 投稿詳細のピン表示と Web に出る。
- 新しいアイテム (作者の検索・登録を含む) を作って保存 → Web のアイテム一覧に出る。
- ピンのドラッグ、並べ替え、削除。
- 縦長・横長の写真で、タップした位置とピンの表示位置が一致する (投稿詳細のピン表示とも一致する)。

## スコープ外

- 元写真からの読み込み (Phase 4)
- ピンの一括適用 (写真ごとに位置が違うため、Web 版にも無い)
- アイテムの編集・削除 (作成のみ)
- Phase 1 / 2 で見送った軽微な問題
